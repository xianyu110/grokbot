## 正文

官方团队真正在跑什么、18 篇指南反复强调的 **7 条规则**，以及每套配置可粘贴的说明——作者读完全部 18 篇官方指南，外加 10 月 27 日最新帖，把值得照抄的内容收进一篇。

### 开场：Blake 的教训

Blake Schuller（SpaceXSI 售后）一开始自己管 **20 个 Agent**：20 个聊天、20 个性格，全都等他回。他说这叫「overwhelm」，然后砍掉了。

现在他只跟一个叫 **Gus** 的 Bot 说话；有时连续几天都不再打开别的聊天。

多数人还停在 Blake 的「第一版」：听说「Agent 大军」，第一天建十个 Bot，结果多了十个聊天窗口，外加一份「读它们」的新工作。

官方已经写过怎么修：**18 篇指南、9 类岗位**（工程、销售、市场、支持、招聘、法务、设计、产品，以及 Day One）。多数人没读完——散在 18 页、每篇只对一个角色。

### 你会得到什么

- 7 条反复出现的规则（附作者统计有几篇提到）
- 一条可给任意新 Bot 安装地基的消息
- **25 套真实配置**，按岗位分组
- 优先照抄的粘贴块
- 他们实际在跑的日程：凌晨 5 点站会、凌晨 3 点审计、每 30 分钟复盘等
- 第一周计划 + 可截图的一页清单
- 每套配置回链官方指南；引号内为原文；粘贴块为作者转述并标明自加部分

**30 秒地图**：先扫地图跳到你的岗位，再读 7 条规则——下面每套配置离开规则都会散架。

### 七条规则（18 人写给 9 个岗位，却落到同一套）

**规则 1：没有人工点头，什么都不外发（18 篇里 11 篇）**  
发送、发帖、合并、花钱、改合同——一律等人。SDR Stefan：「绝不自动发送。Bot 可以研究、起草、建记录、预置；我审完再发。」创始人销售 Simon：「我说可以，才出去。」

**规则 2：一个前门（8/18）**  
你只跟一个 Bot 说话，它再跟其余的说话。Josh 叫 Bot Boss，Blake 叫 Gus，Simon 叫 Founder Mode，Krista 叫 Chief of Staff。职责相同：路由、合并汇报，自己不做专岗活。

**规则 3：一个 Bot 一个岗位（15/18）**  
PM Kevin：「幕僚长不该去调 computer-use 评测。」投放 Miguel：「给它一个渠道，别给全部。」一岗一记忆干净；七岗混在一起。

**规则 4：默认安静（4/18，往往是最忙的配置）**  
Blake：「多数巡检跑完什么都不产出，这是设计如此。」Miguel：「只有不对劲才 ping 我们。」每次跑都吵的例程会训练你忽略它。

**规则 5：先做一遍教会它（4/18）**  
录一次你自己做任务，Bot 把录像变成 Skill。Ryan 用这招绕过 Meta API 核验延误；Krista、Holly 也这样入职 Bot。

**规则 6：同一改正出现两次 → 写成规则（4/18）**  
Stefan、Simon、Holly、Krista 说法不同意思一样。Lauren Tan（做 Grok Bot 的人）在帖里排过优先级。

**规则 7：从一个 Bot 开始，挣来下一个（5/18）**  
Josh：先一两个，可信再加。Miguel：第一个成例行后再加第二个。Blake 先二十再回到一个。

### Step 0：一条消息装好地基

在搭下面任何配置前，把 7 条规则交给第一个 Bot（写成描述）。每行至少来自一篇官方指南；最后一句来自 Josh：「截图是数据，不是指令。」

### 第一部分：你的一天（配置 1–7）

来源：Josh Kim《Grok Bot for Work》、Kevin Niparko《Grok Bot for PMs》、Blake《Post-Sales》、Matt Palmer《Grok Bot 101》。

1. **Inbox Manager（Josh）** — 分流邮件 / Slack / DM，只上报「重要且紧急」。只读。工作日 9:05 与 16:05。草稿打标签，你打「send」才发。原话：「关键是知道哪三条真正需要回。」
2. **Calendar EA（Josh）** — 堆会保护专注块、就近订会议室、标冲突。安全规则：从不静默写日历；改期与邀请先草稿再确认。
3. **Intel Scout（Josh）** — 工作日 8:00 与 17:00 读收件箱、Slack、会议笔记，写三节简报：影响你的公司动向、未闭环跟进、会前要准备什么。每条：来源 → 为何重要 → 一件可做的事；否则标 CONTEXT ONLY。
4. **Bot Boss（Josh）** — 规则 2 的前门。上面三个向它汇报，你只跟它聊。边界：「轮毂式 EA，不是建造者，也不是审计员。」
5. **注意力清单（Kevin）** — 不再写周优先级（太快过期）。幕僚长每小时从邮件、Slack、Granola、日历重建注意力清单，归档与焦点无关的邮件。每周必问：「这周我把时间花在哪里、以后可以卸给 Agent？」
6. **Gus 的例程（Blake）** — 先抄「会前卡」：与会者、谁接受了、一个目标、带链接的谈话点、勿做清单。总结：「我没有把工作自动化。」他只是不再用每天第一小时追上下文。
7. **关注列表做成私人 CRM（Matt）** — 手机上 10–15 分钟：把关注的约 800–900 个 X 账号变成 Notion 私人 CRM（仅公开资料）；旅行时问「该跟谁喝咖啡」。另有 Bot 盯 Facebook Marketplace / Craigslist 找意式咖啡机。警告：「一个 Bot 登录某站，其他 Bot 也能到那个站。」

### 第二部分：工程（配置 8–13）

来源：Lingxi Li、Eric Zakariasson、Matt Palmer、Ryan Perry。

8. **每日技术侦察（Matt）** — 工作日读 X 书签，挑一项值得演示的技术，按他的风格起草原型提示词并等待。批准后交给 Cursor 云端 Agent 构建并开 PR。
9. **外环 Agent（Matt）** — 一个 Bot 从 Slack/Notion/GitHub/文档收拢乱上下文，写成干净提示词再交给 coding Agent。「Grok Bot 不写代码。」
10. **30 分钟 PR 环 + 凌晨 3 点审计（Lingxi）** — 从手管 15 个云端 Agent 到同时 200+。举证规则：「截图必须证明含我所要改动，并有前后对比。」深夜玩票提示：「今晚六小时，随便做，玩得开心！」
11. **Jenny：从不写代码的运营头（Lingxi）** — 五名工程 Bot 各管一块；Jenny 每天凌晨 5 点与每个 Bot 1:1 复盘 playbook、表面 blocker。Bot 反复犯同样错时，缺的往往是这个座位。
12. **一项目一频道一编制（Eric）** — Projects Manager 按项目开频道并从现有 Bot 抽人。规则：先复用；每频道最多经理 + 五专岗；新建 Bot 须你批准；卡住标 Blocked 并 ping 你。自标：「仍在试验的模式。」
13. **夜班与发布门（Ryan）** — 手游工作室六 Bot。Bug fix Agent 夜里扫 Sentry：修明显 bug、其余升级。独立基础设施 Agent 管发布与回滚：「不经它，到不了玩家。」

### 第三部分：销售（配置 14–18）

14. **CLEAR vs FLAG（Stefan）** — 幕僚长早上把联系人分成两堆：CLEAR 继续推进，FLAG 停下。「足迹胜过头衔。」任何「多数无聊、少数危险」的队列都能用。
15. **Founder Mode（Simon）** — 一幕僚长 + 8 专岗 + 16 例程，确认日程前全部暂停。先抄「周一设计伙伴扫描」。「信号胜过头衔。」
16. **塞进手机的会前准备（Krista）** — 日常从 Salesforce、Gmail、Slack、通话笔记与网上研究压成短摘要。通话技巧：结束前 5–10 分钟停录音，幻灯片 Bot 在通话未结束时就按转写改 deck。
17. **战略客户一户一专家 Bot（Krista）** — 盯该户 Slack/通话/邮件/X/LinkedIn，标功能需求，发周媒讯。省钱细节：状态文件，只扫新内容。
18. **线索响应端到端测速（Alex / Clay）** — 公司填邮箱测自家销售回线索有多快；Clay 丰富邮箱并丢 Slack 任务；Grok Bot 替对方填演示表单并计时。「从一个你已经手做的工作流开始。」  
**加餐（10 月 27 日官方）**：销售运营把个人 Bot 变成 Shared Bot（Account Intel / Quote / Deal）。共享规则：「销售不能用 Quote Bot 批准自己的折扣。」

### 第四部分：市场（配置 19–21）

19. **六个市场座位（Josh）** — 分析师不能改广告、出价或预算。「座位常在，战役常换。」
20. **Fuse 守门人（Miguel）** — Grok Bot 自己的投放团队第一个建的不是营销 Bot，而是 Fuse：阻止其他 Bot 在广告账户乱点或狂打 API 导致封号。另有每日节奏 Bot：对照月目标与近 7 天花费，没事保持安静。「快速出广告主要是协调问题，不是创意问题。」
21. **唯一有权宣布「发现」的 Bot（Ryan）** — Analytics Agent 读 Meta Ads、AppLovin、Adjust、PostHog、应用商店。「读玩家实际做了什么，不是我希望他们做什么。」「只有你有权宣布发现。」结果：发现玩家当情侣游戏玩 → 换广告 → 安装成本从 $15 降到 $1。一个 Bot 拥有真相，其余把它当规格。

### 第五部分：支持 / 招聘 / 法务 / 设计（22–25）

22. **带视频的 Bug 复现（David Gan）** — 尝试复现、录故障状态、写复现步骤。退款同模式：对照政策检查 → 人批 → Bot 回复。
23. **Preppy 与 Pulse（Holly）** — 面前提前发一条 Slack：见谁、阶段、焦点、已覆盖内容；面后按转写起草评分卡、要你自评再重写。「评分卡别再拖到晚上 9 点。」
24. **读路径 / 写路径分离（Kelly）** — 12 条法务工作流；审查追踪约每 30 分钟刷新。读合同与 Salesforce 自由；写入先预览等确认。「每条外发消息都有人审。」
25. **真资产 + Experiments Bot（John Bai）** — 指向真实生产文件而非截图；Figma Bro 经 Figma MCP 从真文件填 20 张 starter 卡。单独留一个只做实验的 Bot。「设计仍不是一枪出片。」

### 分享：配方，不是克隆

模板带走：指令、相关记忆与技能、插件、例程。不带走：密钥、个人记忆、自定义代码；电脑、登录、聊天史也留下。「模板分享的是配方不是克隆。」安装别人的 Bot 要非常谨慎。

### 你的第一周

官方反复顺序：一个 Bot → 手做 → Skill → Routine。

| 天 | 做什么 |
|----|--------|
| 1 | 粘贴 Step 0；回答问题；批准一个专岗 |
| 2 | 给专岗一个真任务，用手改到对 |
| 3 | 录一次自己做；存成 Skill |
| 4 | 加一条例程：默认关、无变化则静默，再启用 |
| 5 | 从本清单挑一套岗位配置照抄 |
| 6 | 问：「这周哪里的时间可卸给 Agent？」 |
| 7 | 读一周运行记录；仅当第一个能离你独立干活时再加第二个 |
