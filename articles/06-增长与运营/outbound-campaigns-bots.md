- 两 Agent 分工：Inbox 管域名/邮箱/预热；GTM 管研究、文案、活动与回复
- 先写清业务简报再找人；先 5 行表验证理解再扩量

## 正文

过去两周作者为 Linkedify 做出约 **$2k 销售额**。早期获客时他们研究竞品 LinkedIn 受众、开 Sales Navigator，发现反复抱怨点：想触达更多人，却撞上 LinkedIn 邀请上限。

围绕该问题写外联文案，抓取竞品粉丝，在 Clay 里丰富与打分，再把四五个 LinkedIn 账号载入 Linkedify。外联一周内就开始约到会、变成付费用户。

现在研究与打分用 **Arnie**，周围工作由 **Grok Bot** 管。下文讲的是**今天在用的配置**（可改编的起始指令，不是线上完整提示词导出），而不是声称每一笔近两周销售都经此链路。

有用之处在于：你可以给 Agent 一个岗位，并检查它产出什么——应能得到可用的邮箱、一张打得开的表、可读的消息，以及你能理解的一条活动。

作者建议用 **两个 Agent** 搭起来。

### 1. 创建两个职责清晰的 Agent

**Inbox Agent（邮箱基建）**  
职责：购买并搭建发信域名与邮箱、管服务商、把邮箱接到发送工具、保持预热、跟踪每个邮箱并处理更换。  
工具：域名注册商、Inbox Insiders（或你的邮箱商）、PlusVibe（或发信工具）、提供商支持用 Gmail、邮箱跟踪表。

**GTM Agent（增长外联）**  
职责：研究潜客、用 Arnie 建线索表与写消息、准备活动、经邮件或 LinkedIn 发送、管理潜客回复。  
工具：Arnie、PlusVibe、Linkedify、业务简报、既有客户/联系人名单。

分工：Inbox Agent 对邮箱商说话；GTM Agent 对潜客说话。本指南不必再拆 LinkedIn / 研究 / 文案三个 Bot——这些归 GTM。更大工作区可以再加专岗，但可从这两个开始。

在 Grok Bot：`+` → Create a Bot，分别命名并下发上表职责。给它们正确业务账号访问；走正常登录流程，**密码与密钥不要写进共享跟踪表**。开工前让每个 Agent 确认能看到哪些工作区。约定采购/研究支出上限，以及 GTM 可自动发送的活动与回复范围；边界清晰后可为例行工作给长期许可。

### 2. 先告诉 GTM 你卖什么

在要线索表之前先发业务事实，否则它只能猜受众与 Offer。填空后发送：

```
我们卖的是：[一句话]
网站：[链接]
想触达：[公司类型与岗位]
我们解决的问题：[具体问题]
我们的 Offer：[实际能提供的]
希望对方下一步：[回复 / 演示 / 开会]
首场活动渠道：[邮件或 LinkedIn]
像我语气的消息样例：[粘贴]
需排除的客户、旧联系人、退订：[列表/链接]
研究预算：[上限]

请整理成短活动简报并保存。
先给我看受众与 Offer，再开始研究人。
```

示例（Linkedify）：可测「想用 LinkedIn 做外联的代理机构负责人」，Offer 可以是帮对方机构走一遍活动的讲解——仅作测试假设。你应得到一份可读、可改的短简报；同一份也交给 Inbox Agent，好按正确业务搭发信身份。

### 3. 让 Inbox Agent 搭邮件基建

若只做 LinkedIn，可跳到第 4 节；也可在邮箱预热期间并行准备线索。

**作者路径**：域名注册商 + Inbox Insiders + PlusVibe；并把提供商支持用 Gmail 交给 Inbox Agent。

流程概要：

1. **买核准发信域名**（与主业务域分离）。Agent 按约定名称与预算在注册商下单（作者用 Porkbun）。
2. **下 Inbox Insiders 单**（作者每域 3 个邮箱；加域到订单≠必须把注册迁给服务商）。
3. **给服务商所需**：域名列表、注册商、发信人姓名、邮箱数、配置权限；若你自己改 DNS，Agent 拿精确指令并跟踪到生效。
4. **让服务商进入正确 PlusVibe 工作区**（作者用 Workspace User 邀请）；跟踪邀请发送/接受/确认。
5. **由服务商连接邮箱**（订单含上传则跟支持直到邮箱出现在 PlusVibe；否则按发信工具说明连接）。
6. **打开并核预热**：连接状态、预热开关、**真实预热活动**——仅有「已交付」邮件不够。
7. **你亲自核一次**：打开 PlusVibe Email Accounts，对照订单、看预热设置，确认在连且在暖。

作者经验：一单约 6 天到齐，另一单因域名与工作区权限更久。细节理顺后大约预留一周，让 Agent 追延迟，不要当铁定交期。服务商常说预热 2–3 周；PlusVibe 对新域/新号另有至少 3–4 周建议——按你买的账户指引，并看真实状态再发。标记「就绪」前还要查邮件认证，并做真实收发测试。

**用一张表跟踪每个邮箱**（Notion 或表格），字段建议：业务/域名/地址；服务商/下单日/价格/续费日；搭建状态；发送工作区与连接；预热开始与最近活动；真实活动回复率与弹回率（带日期与发送数）；上次检查/下一步/更换状态。密码密钥不进表。

给 Inbox Agent 的指令要点：按简报与约定预算买域下单；经支持 Gmail 处理问题；跟踪服务商对正确工作区的权限；跟到全部预期邮箱已连接并预热；维护一行一邮箱的跟踪表；返回跟踪表与 PlusVibe 链接；告诉你该打开哪些邮箱做预热抽查；未就绪勿进线上活动。

**若你想自己搭邮件**：同一 Inbox Agent 可用你的注册商与邮箱主机，自行建箱、配 MX/SPF/DKIM/DMARC 并接发信工具；也可装 Frontal 邮件基建技能并改编到你的服务商与 PlusVibe——这是可选手工路线，不是 Inbox Insiders 托管路线的额外必做步骤。

### 4. 把 GTM 接到 Arnie 与发送工具

**Arnie（研究与写作）**：把安装说明给 GTM；若在 Codex/Claude Code 上跑，装在那台电脑。参考 `https://www.arnies.ai/agent-install.txt`。引导登录后确认账户、工具与已装技能。Arnie 已含写作技能，不必另建文案 Bot。

**PlusVibe**：GTM 进入 Inbox 已准备好的同一工作区，能见可用邮箱、建活动、读回复。换箱/加容量仍归 Inbox，GTM 不擅自下单。

**Linkedify**：LinkedIn 外联与自动渐进预热。让 GTM 加载官方 SOP/技能并确认；没有就向 Linkedify 取当前说明，勿瞎猜安装器。检查各账号连接、预热与限额。

你应得到：正确的 Arnie 与发送工作区；LinkedIn 预热归 Linkedify+GTM，邮件预热归 Inbox。

### 5. 先只要 5 个潜客，并打开表

把第 2 节简报给 GTM，让它建议几种找受众的方式、选定一种，再在预算内研究 **5 人**——够判断它是否听懂，再花钱扩表。

要求：用 Arnie 建表，列人、公司、主页/网站、为何匹配、该理由的来源、所选渠道所需联系方式；**返回可点击的表链接**（只有表名/ID 时追问真链接）。

打开前几行：公司、岗位、联系理由；需要时点开源链接。不对就明确纠正，例如：「这些是个人顾问。我要的是有团队的代理机构。改受众再给我五个新例子。」

### 6. 剔除不该联系的人

对照客户表、历史外联、退订：去重、排除不该联系者；已联系过的展示历史而非当新潜客。邮件地址要再验——研究中找到的地址未必可用；失败/不确定的先 Hold。LinkedIn 确认是目标人且可用于该活动。

每行标 **Ready / Hold / Exclude** 并短理由。Ready ≠ 已发送。

### 7. 用 Arnie 写作技能出消息

对 Ready 行：按 Offer 与你的文案样例，准备首条 + 2 条跟进（邮件或 LinkedIn）；用研究事实但别硬编痛点；先给 5 个完整样例与草稿链接，**保持未发送**供你审。

检查：像你吗？事实对吗？Offer 清吗？下一步动作清吗？用白话改：「Offer 说清楚」「太正式」「别假定他们有这个问题，改成提问」——先改样例再铺开。不必另建人设 Bot；你的判断与真实回复仍是迭代的一部分。

### 8. 准备活动，再人工核对

在 PlusVibe 或 Linkedify 准备活动：用已审潜客与消息；已有活动则复用；**批准前保持暂停**。返回：活动链接、选用账号、线索数、日程、5 个收件人预览；上报上传失败或缺项。

点开链接一起看受众、发信账号、时间与文案。邮件用 Inbox 跟踪表里的就绪邮箱；LinkedIn 用已核限额的账号。读真人预览：若仍见 `{{first_name}}`、空白句或错公司，修好再预览。通过后批准受众、消息、账号、日程与量级；GTM 启动约定活动并回报状态。连不上/启不了要明说缺什么——下载 CSV ≠ 活动在跑。

### 9. 管回复并汇报结果

约定 GTM 可自行回答的范围（产品、标准价、搭建流程、可约时段）；例外与无法兑现的承诺交你；退订者停止跟进。

简单报表：已联系、回复、感兴趣回复、会议、成交；邮件与 LinkedIn **分开**。邮件要含各邮箱真实活动回复率（区间、联系人数；分子用唯一回复潜客；排除预热与自动回复；百分比旁写计数），并与 Inbox 共享。

回复骤降：Inbox 查连接与是否进垃圾箱；投递健康但不感兴趣：GTM 改受众、Offer、文案。

### 10. Inbox 每周对账例程

搭建不是一次性。每周例程：对照 PlusVibe 核对跟踪表；找断连、停预热、失败搭建、需关注/更换的邮箱。真实潜客回复率下降即使预热分好看也要调查；同时看弹回。样本要够；一封没回 ≠ 邮箱坏了。先查投递与账户健康，再与 GTM 区分「投递问题」与「定向/文案弱」。确认表现差再换箱，换箱先预热再交接。

保存后让 Agent **展示已存日程与下次运行**——「我会每周检查」≠ 已调度例程。看首次运行：表上应有各邮箱检查时间与变更。成本也记在这：域名续费、邮箱费、发信软件、更换；GTM 另记研究支出——看到的是运行成本，不只首购。

### 第一版「能跑」长什么样

- **Inbox Agent**：Notion/表格里的邮箱清单、PlusVibe 已连账号、你亲自核过的预热、已保存的周例程。  
- **GTM Agent**：Arnie 表里合适的潜客与消息、PlusVibe/Linkedify 里已审活动、回复有人负责。  

从一个受众开始，先检查前几个人与几条消息；对了再让同样 Agent 重复放大。结果站得住再加量。
